23 种设计模式速记：口诀、Java 示例与常见疑问

发表于 2026-10-21 分类于 技术笔记 ， 设计模式
把 23 种设计模式按创建型、结构型、行为型整理成一份速记：每个模式一句核心、一个 Java 小例子，最后附上 23 个常见疑问。

这是我自己整理的一份设计模式速记。23 个模式按创建型、结构型、行为型分开，每个模式保留一句核心、一个能跑的小例子，最后把学习过程中卡住的问题汇成 Q&A。

代码是 Java，示例尽量短，能省的行都省了；个别片段补了 import，其余按需自行补。

类型 数量 关心什么
创建型 5 对象怎么来
结构型 7 对象怎么拼
行为型 11 对象怎么交互

口诀：创建型「抽工建单原」，结构型「桥适组装享外代」，其余是行为型。

  • 抽工建单原 = 抽象工厂、工厂方法、建造者、单例、原型
  • 桥适组装享外代 = 桥接、适配器、组合、装饰、享元、外观、代理

创建型模式

Factory 管“造哪个”，Abstract Factory 管“造一族”，Builder 管“怎么一步步造”，Prototype 管“照着造”，Singleton 管“只造一个”。

模式 核心 关键结构
Factory Method 子类决定 new 哪个 抽象工厂类 + 子类实现创建
Abstract Factory 创建一族相关对象 抽象工厂接口 + 多个产品接口
Builder 分步构造复杂对象 Builder + 链式调用 + build
Prototype 克隆现成对象 clone / copy
Singleton 全局唯一实例 私有构造 + 静态实例

1. Factory Method 工厂方法

父类定创建接口，子类决定 new 哪个。

核心：创建延迟到子类。

2. Abstract Factory 抽象工厂

创建一族相关对象。

核心：一族产品一起换，不混搭。
工厂方法是一个方法创建一个产品；抽象工厂是一组方法创建一族产品。

3. Builder 建造者

分步构造复杂对象。

核心：构造过程分步，最后 build。
和工厂的区别：工厂关心“创建哪个”，Builder 关心“怎么一步步建”。

4. Prototype 原型

克隆一个现成对象。

核心：以现有对象为模子复制新对象。
适合创建成本高、或需要保留母版再改副本的场景。

注意：Java 的 clone() 是浅拷贝，对象里有引用类型时要小心深拷贝。

5. Singleton 单例

全局只有一个实例。

核心：私有构造 + 静态实例 + 全局访问点。

枚举单例天然防反射、防序列化破坏，工程里更推荐。

结构型模式

结构型模式都在解决“对象怎么组合、怎么复用、怎么控制访问”。

模式 核心
Adapter 转接口
Bridge 拆维度
Composite 树形统一
Decorator 包一层加功能
Facade 统一入口
Flyweight 共享对象省内存
Proxy 控制访问

1. Adapter 适配器

接口不兼容，加个转接头。

核心：不改老代码，包一层转接口。

2. Bridge 桥接

抽象和实现分离，两个维度独立扩展。

核心：形状和颜色各自扩展，不搞类爆炸。

3. Composite 组合

树形结构，叶子/容器统一处理。

核心：文件和文件夹统一当节点处理，递归调用。

4. Decorator 装饰

不改进原类，包一层加功能。

核心：一层层包装，动态加功能，不改原类。

5. Facade 外观

给子系统一个统一入口。

核心：封装复杂调用，对外只给一个简单接口。

6. Flyweight 享元

共享细粒度对象，省内存。

核心：内部状态共享，外部状态由调用方传入。

7. Proxy 代理

替原对象控制访问。

核心：代理控制对真实对象的访问，可加懒加载、权限、日志。

行为型模式

行为型模式都在解决“对象之间怎么交互、职责怎么分配、变化怎么隔离”。

模式 核心
Interpreter 语法变对象树，递归解释
Template Method 父类定流程，子类填步骤
Chain of Responsibility 请求沿链传，能处理就停
Command 请求封装成对象，可撤销可排队
Iterator 统一遍历，不暴露内部结构
Mediator 多对多走中介，变一对多
Memento 状态快照，随时恢复
Observer 一变多通知，发布订阅
State 状态决定行为，自动迁移
Strategy 算法族可互换，运行时切换
Visitor 数据与操作分离，加操作不改原类

1. Interpreter 解释器

解释自定义语法/表达式。

核心：把语法规则抽象成对象树，递归解释。

2. Template Method 模板方法

父类定骨架，子类填步骤。

核心：流程父类定，步骤子类填。
框架里的钩子方法就是这个套路。

3. Chain of Responsibility 责任链

请求沿链传，能处理就处理，否则下一个。

核心：链式传递，谁合适谁处理，可中断可传递。

4. Command 命令

把请求封装成对象。

核心：请求变成对象，可存、可排队、可撤销、可记录日志。

5. Iterator 迭代器

统一遍历集合。

核心：遍历逻辑从集合里抽出来，调用方不关心内部结构。

6. Mediator 中介者

对象不直接通信，走中介。
中介者模式是迪米特法则（Law of Demeter, LoD）（最少知识原则（Least Knowledge Principle, LKP））典型应用 。

核心：多对多通信变一对多，同事类之间不直接引用。

7. Memento 备忘录

保存状态，之后恢复。

核心：状态快照存到外部，需要时恢复，不破坏封装。

8. Observer 观察者

一变多通知，发布订阅。

核心：发布者不关心谁订阅，订阅者自动收到通知。

9. State 状态

状态决定行为，状态可迁移。

核心：状态自己决定下一步，避免一堆 if-else。

10. Strategy 策略

算法族可互换。

核心：算法独立成类，运行时可换。
和 State 的区别：Strategy 是外部主动换算法；State 是状态自己决定行为。

11. Visitor 访问者

外部给对象加操作，不改原类。

核心：数据结构和操作分离，加新操作不改元素类。

常见问题

Q1：23 种设计模式怎么分类？
A：

  • 创建型：管“对象怎么来”。
  • 结构型：管“对象怎么拼”。
  • 行为型：管“对象怎么交互”。

Q2：创建型五个怎么区分？
A：

  • Factory Method：父类定创建接口，子类决定 new 哪个。
  • Abstract Factory：创建一族相关对象。
  • Builder：分步构造复杂对象。
  • Prototype：克隆现成对象。
  • Singleton：全局唯一实例。

一句话：工厂管“造哪个”，抽象工厂管“造一族”，Builder 管“怎么一步步造”，Prototype 管“照着造”，Singleton 管“只造一个”。

Q3：抽象工厂和工厂方法差不多？
A：像，但不一样。

  • 工厂方法：创建一个产品。
  • 抽象工厂：创建一族配套产品。
  • 抽象工厂里每个 createX() 可以看作一个工厂方法。
  • 但抽象工厂多了“产品族必须配套”的约束。

Q4：结构型七个怎么区分？
A：

  • Adapter：转接口。
  • Bridge：拆维度，用组合代替继承。
  • Composite：树形结构，叶子/容器统一处理。
  • Decorator：包一层加功能。
  • Facade：统一入口，简化调用。
  • Flyweight：共享对象，省内存。
  • Proxy：控制对真实对象的访问。

Q5：Bridge 就是关联关系吗？
A：结构上常用关联/组合实现，但有关联不等于 Bridge。
Bridge 的关键是：两个独立变化的维度，各自扩展，避免继承爆炸。

Q6：Composite 为什么好用？
A：它把文件和文件夹统一成同一种节点。
调用方不用区分叶子和容器，递归处理即可。菜单树、组织架构、UI 容器都是这个套路。

Q7：Facade 和 Abstract Factory 能坐一桌吗？
A：都封装，但不是一类。

  • Facade：结构型，简化调用，给子系统统一入口。
  • Abstract Factory：创建型，封装创建一族对象。

Q8：Proxy 懒加载怎么理解？
A：代理层先暂存参数或条件，不急着创建真实对象。
第一次真正需要时才创建。核心就是：先记账，后干活。

Q9：Flyweight 工厂静态方法为什么能 new 非静态类？像单例吗？
A：static 方法属于类，可以 new 任意对象、访问静态成员。
Flyweight 按 key 共享多个对象；Singleton 全局只允许一个实例。像，但不一样。

Q10：行为型怎么记？
A：

  • Interpreter：语法变对象树，递归解释。
  • Template Method：父类定流程，子类填步骤。
  • Chain of Responsibility：请求沿链传。
  • Command：请求封装成对象。
  • Iterator：统一遍历。
  • Mediator：多对多走中介。
  • Memento：状态快照。
  • Observer：发布订阅。
  • State：状态决定行为。
  • Strategy：算法族可互换。
  • Visitor：数据与操作分离。

Q11：解释器一定要用栈吗？像编译原理、状态机吗？
A：不一定用栈，递归或对象树也可以。
它像编译原理里“语法树 + 求值”那一小部分，不是完整编译器。
本质不是状态机，核心是语法树递归求值。

Q12：责任链里 next 没定义为什么能用？
A：next 定义在父类 Handler 里，通常是 protected 字段。
子类继承后可以直接访问。责任链本质就是手动拼了一个单向链表。

Q13：Command 不就是函数吗？
A：很多 Command 可以用函数、Runnable、Consumer 替代。
Command 多出来的是“对象化”：可排队、可撤销、可记录日志、可组合成宏命令。

Q14：增强 for 循环编译后会生成迭代器吗？
A：实现 Iterable 的集合会生成 Iterator。
数组的增强 for 编译后是普通下标循环。

Q15：群聊是不是 Mediator 实现的？
A：核心模型就是中介者。用户不直接互发，统一发给聊天室，聊天室转发。
真实群聊还涉及持久化、离线消息、多设备同步、消息顺序等，工程更复杂。

Q16：Memento 不就是栈吗？哈希表也可以？
A：Memento 是“状态快照对象”。
栈、HashMap 是存放快照的容器。
撤销常用 Stack<Memento>，存档可用 Map<String, Memento>。

Q17：Observer 名字绕，能叫分发节点吗？
A：可以。
Subject 就是发布者、事件源、分发节点。
Observer 就是订阅者、接收者、监听器。

Q18：Visitor 为什么绕？什么叫双重分派？
A：Java 是单分派，直接 visitor.visit(node) 不能按运行时类型走。
所以绕两次：

  1. node.accept(visitor) 确定元素类型。
  2. visitor.visit(this) 确定访问者类型。

好处：加新操作不改节点。
坏处：加新节点类型要改所有 Visitor。

Q19：Visitor 不适合 Java？工具类更好？
A：业务代码里，工具类静态方法通常更直白。
Visitor 适合：操作多、节点稳定、不想写 instanceof 的场景，比如编译器、解析器、代码分析。
Java 单分派导致 Visitor 绕；其他语言用动态分派、多分派、密封类 + 模式匹配替代。

Q20：一段代码能同时是多个模式吗？
A：能。模式是视角，不是互斥标签。
一个类可以同时是 Singleton、Facade，内部又用 Factory 和 Strategy。

Q21：Visitor 是不是语言补丁？
A：是。
它本质是在单分派语言里模拟多分派。
语言进步后，很多补丁被固化进语法，比如 Kotlin 的 sealed + when、Rust 的 enum + match。

Q22：Facade 门面模式是什么？
A：门面模式就是外观模式，同一个东西。
核心：对外给统一、稳定的高层接口，把内部复杂调用包起来。
平台对多产品接口耦合时，平台侧加 Facade 收口，产品只依赖 Facade。

Q23：产品要利用门面模式重构，谁重构？平台还是产品？
A：被依赖的公共底座重构，通常是平台侧。
思路：平台加 Facade，对外稳定，对内吸收变化。
产品只依赖 Facade，不再因平台内部接口变化而联动修改。
再进一步，可演进为插件化。
